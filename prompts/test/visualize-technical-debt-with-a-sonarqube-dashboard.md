# Visualize Technical Debt with a SonarQube Dashboard

Get a SonarQube guide covering technical debt metrics, dashboard setup, quality gates, and reports for developers and management.

Variables: language

## Prompt

I have set up SonarQube to analyze my {{language}} project, and it's generating a lot of data about code smells, bugs, and vulnerabilities. Now I need to create a compelling dashboard to visualize this technical debt for both my development team and for management.

Your task is to guide me on how to best utilize SonarQube's features to create an effective technical debt dashboard and report. Please cover:

1.  **Key Metrics:** What are the most important SonarQube metrics to track for technical debt? (e.g., Code Smells, Duplication, Complexity, Coverage). Explain what each metric means and why it's important.
2.  **Dashboard Configuration:** How to configure a custom SonarQube dashboard to highlight these key metrics. What widgets are most useful for this purpose?
3.  **Quality Gates:** How to set up a Quality Gate in SonarQube to enforce a minimum standard of code quality for new code. Provide a sample Quality Gate configuration that is strict but realistic.
4.  **Reporting to Management:** How to extract the data from SonarQube and present it in a way that is understandable to non-technical stakeholders. Suggest a format for a weekly or monthly technical debt report.

Output should be a strategic guide to using SonarQube for technical debt management, not just analysis.

## Tips

Data visualization is key to getting buy-in for technical debt reduction efforts.
