# Analyze and Reduce the Size of a Webpack Bundle

Your web app's initial load time is slow because the JavaScript bundle Webpack generates is too large.

Variables: framework

## Prompt

My `{{framework}}` application's initial load time is slow, and I suspect it's because the JavaScript bundle generated by Webpack is too large. I need a systematic way to analyze my bundle and find opportunities to reduce its size.

Your task is to provide a guide on using `webpack-bundle-analyzer` to do this.

1.  **Installation and Setup:** How to install and configure `webpack-bundle-analyzer` as a Webpack plugin.
2.  **Analyzing the Report:** The tool generates a treemap visualization of the bundle. Explain how to read this report. What do the different colors and sizes of the boxes mean? How do I identify the largest dependencies in my bundle?
3.  **Common Size Reduction Techniques:** Based on the analysis, what are the common techniques for reducing bundle size? Provide actionable advice for:
    *   **Code Splitting:** How to use dynamic `import()` to split large parts of the application (like routes or heavy components) into separate chunks that are loaded on demand.
    *   **Tree Shaking:** Explain what tree shaking is and how to ensure it's working correctly (e.g., by using ES modules correctly).
    *   **Dependency Swapping:** If a large dependency is identified (e.g., Moment.js), suggest smaller, more modern alternatives (e.g., `date-fns` or `dayjs`).
4.  **Tracking Progress:** How to use the analyzer's report to track the bundle size over time and ensure it doesn't regress.

Output should be a practical guide to a critical web performance optimization task.

## Tips

For any non-trivial web app, bundle size analysis is a mandatory skill for frontend developers.
