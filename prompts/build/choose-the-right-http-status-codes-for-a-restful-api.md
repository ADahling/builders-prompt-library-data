# Choose the Right HTTP Status Codes for a RESTful API

Master the implementation of standard HTTP status codes in RESTful APIs through a categorized guide of success, client, and server errors.

## Prompt

I am developing a RESTful API and I want to make sure I am using the correct HTTP status codes in my responses. 

Your task is to create a guide that explains when to use the most common HTTP status codes.

**Instructions:**
1.  **Success Codes (2xx):** Explain the difference between 200 (OK), 201 (Created), and 204 (No Content). Provide an example for each.
2.  **Client Error Codes (4xx):** Explain when to use 400 (Bad Request), 401 (Unauthorized), 403 (Forbidden), and 404 (Not Found). Provide an example for each.
3.  **Server Error Codes (5xx):** Explain when to use 500 (Internal Server Error), 502 (Bad Gateway), and 503 (Service Unavailable). Provide an example for each.

**Output Format:**
Provide the output as a Markdown document. For each status code, provide a clear explanation of its meaning and a practical example of when to use it in a RESTful API.
