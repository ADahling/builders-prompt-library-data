# Implement CQRS and Event Sourcing for a Complex Domain

Design a robust CQRS and Event Sourcing architecture with code examples to ensure auditability and scalability in complex domain models.

Variables: application_type, user_persona, programming_language

## Prompt

You are a software architect with deep expertise in Domain-Driven Design (DDD), Command Query Responsibility Segregation (CQRS), and Event Sourcing. I need your help to design and implement these patterns for a new feature in our {{application_type}} application.

**Feature Context:**
The new feature is a collaborative workflow management tool for {{user_persona}}. It involves complex business logic, multiple actors, and a need for a complete audit trail of all actions performed.

**Your Task:**
Provide a detailed guide on how to apply CQRS and Event Sourcing to this feature. The guide should include code examples and best practices.

**Instructions & Constraints:**
1.  **Domain Model:**
    *   Based on the feature description, identify the aggregates, entities, and value objects in the domain.
    *   Define the commands (actions that change the state) and events (outcomes of the commands) for the primary aggregate.

2.  **CQRS Implementation:**
    *   **Write Side (Command Side):** Design the command handling logic. Show how commands are validated and how they result in the creation of events. Provide code examples in {{programming_language}}.
    *   **Read Side (Query Side):** Design the read model that is optimized for querying. Explain how the read model is updated asynchronously from the events generated by the write side. Provide code examples for the projection logic.

3.  **Event Sourcing Implementation:**
    *   Design the event store. You can use a dedicated event store database (e.g., EventStoreDB) or a general-purpose database (e.g., PostgreSQL, Cassandra).
    *   Show how to save events to the event store and how to rebuild the state of an aggregate from its event stream. Provide code examples.

4.  **Architectural Considerations:**
    *   Explain how to handle eventual consistency between the write and read sides.
    *   Discuss strategies for versioning events as the domain model evolves.
    *   Describe how to implement snapshots to optimize the loading of long-lived aggregates.

**Output Format:**
Generate a technical design document in Markdown with the following structure:
1.  **Domain Model Overview**
    *   Aggregates and Entities
    *   Commands and Events
2.  **CQRS Implementation Guide**
    *   Write Side Design (with code examples)
    *   Read Side Design (with code examples)
3.  **Event Sourcing Implementation Guide**
    *   Event Store Design
    *   Saving and Replaying Events (with code examples)
4.  **Advanced Architectural Patterns**
    *   Handling Eventual Consistency
    *   Event Versioning Strategies
    *   Snapshotting Aggregates
