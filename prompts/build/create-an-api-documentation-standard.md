# Create an API Documentation Standard

Draft a Markdown API documentation standard for microservices with endpoint sections, examples, and a justified tooling recommendation.

## Prompt

My team is building multiple microservices, and we need to establish a consistent standard for API documentation to ensure that all our APIs are well-documented and easy to use.

Your task is to create a comprehensive API documentation standard.

**Instructions:**
1.  **Documentation Sections:** Define the essential sections that should be included in the documentation for every API endpoint. These sections should include:
    *   Endpoint URL and HTTP method
    *   A clear description of what the endpoint does
    *   Request parameters (path, query, and body parameters) with their data types and validation rules
    *   Example request
    *   Success and error responses with their status codes and example bodies
2.  **Tooling:** Recommend a tool for generating and hosting the API documentation (e.g., Swagger/OpenAPI, Postman, Slate). Justify your recommendation.

**Output Format:**
Provide the output as a Markdown document. First, list and describe the essential documentation sections. Then, recommend a documentation tool and explain why you chose it.
