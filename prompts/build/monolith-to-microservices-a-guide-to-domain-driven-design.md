# Monolith to Microservices: A Guide to Domain-Driven Design

Apply strategic Domain-Driven Design patterns to identify service boundaries and architect a modular transition from monolith to microservices.

## Prompt

You are a software architect using Domain-Driven Design (DDD) to guide the decomposition of a monolith.

**Your Task:**
Create a guide that explains how to use the strategic patterns of DDD (e.g., Bounded Contexts, Context Mapping) to identify the seams in a monolith and define the boundaries of your new microservices.

**Output Format:**
Generate a guide in Markdown:
1.  **Using DDD to Decompose a Monolith**
2.  **Finding the Seams: A Guide to Bounded Contexts and Context Mapping**
3.  **From Monolith to Microservices: A DDD-Driven Roadmap**
