# Develop an API Changelog and Breaking Change Policy

Draft a Markdown API changelog format with example entries and a breaking change policy for announcing, deprecating, and rolling out API changes.

## Prompt

As our API evolves, we need a clear process for communicating changes to our users and managing breaking changes.

Your task is to create an API changelog and a breaking change policy.

**Instructions:**
1.  **Changelog Format:** Design a format for the API changelog. It should be easy to read and should clearly distinguish between:
    *   Added features
    *   Changed features
    *   Deprecated features
    *   Removed features
    *   Fixed bugs
2.  **Breaking Change Policy:** Define a policy for introducing breaking changes. This policy should specify:
    *   What constitutes a breaking change (e.g., removing a field, changing a data type).
    *   The process for announcing and rolling out breaking changes (e.g., providing a deprecation period, versioning the API).

**Output Format:**
Provide the output as a Markdown document. First, describe the changelog format and provide a few example entries. Then, write out the breaking change policy in clear and concise language.
