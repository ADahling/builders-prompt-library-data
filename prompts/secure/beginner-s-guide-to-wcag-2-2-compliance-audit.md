# Beginner's Guide to WCAG 2.2 Compliance Audit

Generate a structured WCAG 2.2 accessibility audit report to identify compliance gaps across perceivable, operable, and robust standards.

## Prompt

You are tasked with conducting a compliance audit for a web application to ensure it meets the Web Content Accessibility Guidelines (WCAG) 2.2 standards. The goal is to identify areas where the application may fall short of accessibility requirements, focusing on usability for individuals with disabilities. Your task is to create a checklist that covers the major aspects of WCAG 2.2 compliance. Consider the following aspects:

1. **Perceivable**: Ensure all content is available to the senses, either through the browser or assistive technologies. Check for text alternatives for non-text content, captions for multimedia, and adaptable content.

2. **Operable**: Make sure the interface is operable by everyone. Verify that all functionalities are accessible via keyboard, provide sufficient time for users to read and use content, and avoid content that could cause seizures.

3. **Understandable**: Confirm that both the content and interface are understandable. Ensure that text is readable and predictable, and provide input assistance to help users avoid and correct mistakes.

4. **Robust**: Content must be robust enough to be interpreted by a wide variety of user agents, including assistive technologies. Check for compatibility with current and future user agents.

Please provide a detailed explanation of each checklist item, why it is important, and suggestions for improvement if the application does not meet these criteria. The output should be a structured audit report including an executive summary, the detailed checklist with explanations, and prioritized recommendations for addressing any compliance issues identified.

## Tips

Use this prompt when you need to audit a web application for WCAG 2.2 compliance, especially if you are new to accessibility standards. The output will guide you through creating a comprehensive checklist and report, ensuring the application is accessible to all users, including those with disabilities.
