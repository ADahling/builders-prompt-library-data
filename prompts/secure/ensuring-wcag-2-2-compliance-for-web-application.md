# Ensuring WCAG 2.2 Compliance for Web Application

Conduct a systematic accessibility audit of web applications to identify and resolve WCAG 2.2 non-compliance issues across all components.

Variables: project_name, section_name, compliance_level, issues, solutions, timeline

## Prompt

You are tasked with ensuring that your web application, {{project_name}}, is fully compliant with the WCAG 2.2 guidelines. Begin by identifying the main sections and functionalities of your application. For each section, consider the following steps: 

1. **Perceivable**: Ensure that all non-text content, such as images or videos, have alternative text descriptions. Check that text can be resized up to 200% without loss of content or functionality. 

2. **Operable**: Verify that all interactive elements are keyboard accessible, and provide keyboard shortcuts for frequently used actions. Ensure that pages have titles that describe their topic or purpose.

3. **Understandable**: Ensure that your content appears and operates in predictable ways. Include labels and instructions where user input is required.

4. **Robust**: Confirm that your content is compatible with current and future user tools, including assistive technologies.

Document your findings for each section, noting any areas that do not meet the criteria and proposing solutions or enhancements. Provide a summary report in the following format:

- **Section Name**: {{section_name}}
  - **Current Compliance Level**: {{compliance_level}}
  - **Issues Identified**: {{issues}}
  - **Proposed Solutions**: {{solutions}}
  - **Implementation Timeline**: {{timeline}}

This prompt is intended to guide developers in upgrading or auditing their web applications for WCAG 2.2 compliance. Use this as a systematic approach to evaluate and enhance accessibility features.

## Tips

Use this prompt when you need to review and ensure that a web application meets the latest WCAG 2.2 accessibility standards. It provides a structured approach to identify, document, and address compliance issues across different sections of the application.
