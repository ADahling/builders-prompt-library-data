# Ensuring WCAG 2.2 Compliance for Web Projects

Audit, implement, and document WCAG 2.2 compliance for web projects using automated tools, core principles, and accessible code patterns.

Variables: project_name, tech_stack

## Prompt

As a web developer, your task is to ensure that your project, {{project_name}}, complies with the Web Content Accessibility Guidelines (WCAG) 2.2 standards. The goal is to enhance accessibility for users with disabilities. Follow these steps to assess and improve accessibility:

1. **Technology Stack**: Specify the technology stack used in your project, such as {{tech_stack}}, as this will influence how you implement accessibility features.

2. **Audit Current Accessibility**: Use tools like WAVE or Axe to conduct an initial audit of your web pages. Identify any existing accessibility issues, such as insufficient color contrast, missing alt text, or non-semantic HTML elements.

3. **Implement Core Principles**: Ensure that your project adheres to the four core principles of WCAG 2.2: Perceivable, Operable, Understandable, and Robust. Provide examples of how you will implement features such as keyboard navigation, screen reader support, and adaptable content layouts.

4. **Testing**: Describe your plan for testing your website's accessibility, including user testing with individuals who have disabilities and automated testing tools.

5. **Documentation**: Document each step taken to achieve compliance, including code changes and testing results, to create a comprehensive accessibility report.

Provide a detailed plan with specific code examples where applicable. Ensure the output is structured with clear headings for each section.

Output Format:
- **Audit Findings**: List of identified issues and tools used.
- **Implementation Plan**: Steps and code examples for each WCAG principle.
- **Testing Strategy**: Methods and tools used for accessibility testing.
- **Documentation**: Summary of actions taken with links to documentation.

## Tips

Use this prompt when needing to ensure a web project complies with WCAG 2.2 standards. It guides developers through assessing current accessibility issues, implementing necessary changes, testing, and documenting the process, making it suitable for intermediate-level developers.
